# Шеф — кулинарный чат с LLM

Одностраничное веб-приложение: тематический чат с языковой моделью Google Gemini.
Тема — **кулинарный ассистент**: подсказывает, что приготовить из имеющихся продуктов,
даёт рецепты с граммовками и шагами, объясняет техники и замены ингредиентов.
На вопросы не по теме вежливо отказывается.

- **Бэкенд:** Python 3.10+, FastAPI, SQLite, httpx
- **Фронтенд:** HTML + CSS + JavaScript (ES-модули, без фреймворков и сборки)
- **LLM:** Google Gemini API (REST)

## Запуск

Нужен ключ Gemini API — бесплатно на <https://aistudio.google.com/apikey>.

### Локально

```bash
git clone git@github.com:Zhmuda/test_task_chat_bot.git && cd test_task_chat_bot
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # впишите ACCESS_KEY и GEMINI_API_KEY
uvicorn app.main:app --port 8000
```

Откройте <http://localhost:8000> и введите значение `ACCESS_KEY` из `.env`.

### Через Docker

```bash
cp .env.example .env        # впишите ACCESS_KEY и GEMINI_API_KEY
docker compose up --build
```

### Тесты

```bash
pip install -r requirements-dev.txt
pytest
```

Тесты подменяют LLM фейковым клиентом и не ходят во внешнюю сеть.

### Переменные окружения

| Переменная        | Обязательна | Описание |
|-------------------|:-----------:|----------|
| `ACCESS_KEY`      | да | Ключ доступа к приложению: 8–255 символов, `A-Z a-z 0-9 - _` |
| `GEMINI_API_KEY`  | да | Ключ Google Gemini API |
| `GEMINI_MODEL`    | нет | Модель, по умолчанию `gemini-flash-latest` |
| `GEMINI_PROXY`    | нет | Прокси только для запросов к Gemini (`http://…`, `socks5://…`) — если API недоступен из вашего региона |
| `COOKIE_SECURE`   | нет | `true`, если приложение работает за HTTPS |
| `DATABASE_PATH`   | нет | Путь к файлу SQLite, по умолчанию `data/chat.sqlite3` |

### Авторизация

1. Пользователь вводит ключ; форма валидирует его на лету (длина 8–255, допустимые символы),
   кнопка «Войти» заблокирована, пока ключ некорректен. Тот же формат повторно проверяется на сервере.
2. Ключ **один раз** отправляется в теле `POST /api/auth/login` (не в URL — не попадает в логи и историю браузера).
3. Сервер сравнивает его с `ACCESS_KEY` из окружения через `hmac.compare_digest` — за постоянное время,
   чтобы исключить timing-атаку. Неудачные попытки ограничены: 5 в минуту с одного IP.
4. При успехе сервер генерирует случайный токен сессии (`secrets.token_urlsafe(32)`) и кладёт его в cookie
   с флагами `HttpOnly` (недоступна JS → не украсть через XSS), `SameSite=Strict` (защита от CSRF)
   и `Secure` при `COOKIE_SECURE=true`. Срок жизни — 7 дней.
5. В базе хранится только **SHA-256 хэш** токена: даже утечка файла БД не даёт рабочих сессий.
   Сессии переживают перезапуск сервера, при выходе запись удаляется — старый токен становится недействительным.
6. Сам ключ на клиенте **нигде не сохраняется** (ни в `localStorage`, ни в памяти после входа) —
   поле очищается сразу после успешного логина.

Почему не «передавать ключ в каждом запросе» или JWT в `localStorage`: в обоих случаях секрет доступен
JavaScript и уязвим к XSS, а отозвать его нельзя. Серверная сессия в HttpOnly-cookie проще и безопаснее
для приложения, где фронт и бэк живут на одном домене.

### Чат и история

- Сообщение валидируется и на клиенте, и на сервере: 1–500 символов, строка из одних пробелов не отправляется.
  Пока модель отвечает, кнопка отправки и очистки заблокированы, показывается индикатор набора.
- Модели передаётся системный промпт и последние 10 сообщений как контекст диалога — можно задавать уточняющие вопросы.
- Если запрос к API упал, пользователь видит понятное сообщение (таймаут, лимит запросов, ошибка модели),
  а его текст возвращается в поле ввода для повторной отправки. Неудачная попытка в историю не пишется.
- История хранится в SQLite (`data/chat.sqlite3`), поэтому сохраняется при перезагрузке страницы и перезапуске.
  Каждая запись — роль, текст и время (UTC на сервере, отображается в локальном часовом поясе браузера,
  с разделителями «Сегодня / Вчера / дата»).

## Что можно доработать

- **Стриминг ответа** (SSE / `streamGenerateContent`), чтобы текст появлялся по мере генерации.
- **Несколько чатов и пользователей** — сейчас по ТЗ один общий чат и один ключ; можно добавить таблицу пользователей
  с хэшированными ключами (argon2) и привязку истории к пользователю.
- **Пагинация истории** — подгрузка старых сообщений при прокрутке вместо отдачи всей истории разом.
- **Async-стек** — `httpx.AsyncClient` + `aiosqlite` вместо синхронных обработчиков в пуле потоков; миграции (Alembic) при росте схемы.
- **Rate limit в Redis** — сейчас счётчик попыток входа в памяти процесса и сбрасывается при рестарте; также лимит на запросы к модели.
- **Полноценный markdown** (таблицы, блоки кода) через проверенную библиотеку + санитайзер (DOMPurify), копирование ответа в один клик.
- **CSP-заголовки**, HTTPS через reverse-proxy (Caddy/nginx) в docker-compose.
- **E2E-тесты фронтенда** (Playwright) и CI на GitHub Actions с линтерами (ruff, mypy).
